# Material GRUB 1.0.0

Material GRUB is now one part of **Material Boot**: the GRUB theme, the optional boot splash and one installer that handle them together. Your GRUB menu looks the same and everything you did with `material-grub` still works. What's new is what's around it, plus a pile of fixes for screens that weren't drawn right.

## Highlights

### One installer for everything
The Material Boot bundle (attached to the [material-boot-core 1.0.0 release](https://github.com/LucaCraft89/material-boot-core/releases/tag/v1.0.0)) installs Material GRUB and, if you want it, the boot splash in one go. If Material GRUB is already installed, it is updated in place and **your settings are kept**.

### A boot splash that matches the menu (optional)
[Material Plymouth](https://github.com/LucaCraft89/material-plymouth/releases/tag/v1.0.0) is a separate, optional part: the loading screen you see after the menu continues the same look, colours and distro logo. If you use the GUI, it gets a **Boot splash** page, and *Apply* updates the menu first and the splash second. If the splash fails, it puts itself back and leaves your menu applied.

### Safer updates
- The installer notices an existing install, tells you what it is about to change before it changes it, and backs up the files it touches (they come back if a step fails).
- It refuses to downgrade, and won't overwrite a package's files with a source install unless you say `--force`.
- Your settings, colours and presets survive.

### A new `material-boot` command
`material-boot grub ...`, `material-boot plymouth ...` and `material-boot core ...` (shared settings, health checks, updates). **`material-grub` stays exactly as it is**, so your scripts, hooks and habits keep working.

## Fixed
- **The theme filled only a corner of the screen** on laptops with unusual screens (seen on 1366x768), with gray edges at the bottom and right. The theme is now built for your exact screen size and centred.
- **A screen mode nobody can use** (a typo, `keep`, 99999x5) no longer ends in a gray or empty screen: you get a plain, readable menu instead.
- **Ventoy sticks** now default to your own screen's size, and any `WxH` works.
- `material-grub doctor` now compares the configured mode with the theme in use and with your display's native mode, so mismatches are reported.

## Good to know
- **Python 3.9 or newer is required.** (The docs said 3.8, but it never worked there.) The installer finds it or tells you which package to install.
- **The packages now need `material-boot-core`** (1.0.0 or newer). Installing the bundle takes care of that. The rpm, deb and Arch packages are built and tested in CI, but they are not attached to this release page.
- Versions: Material GRUB, Material Plymouth and Material Boot Core all start together at **1.0.0**.

## How we tested it (and what we didn't)
Tested in containers on Fedora, Debian, Ubuntu, Arch and openSUSE: a real install, an update over an older version, a real version bump (1.0.0 to 1.0.1) through the package manager, and removal leaving nothing behind. The installed result was also booted in a virtual machine (QEMU) and shows the Material menu at 1920x1080.

**Not tested yet:** a real computer (real graphics hardware and firmware), and immutable systems such as Fedora Silverblue or SteamOS (the installer doesn't support them yet). Keep a way to recover your boot before you try it on a machine you can't afford to break.

## Install
```
sha256sum -c material-boot-1.0.0.tar.gz.sha256
tar xzf material-boot-1.0.0.tar.gz && cd material-boot-1.0.0
./install.sh --dry-run        # shows what would change, touches nothing
sudo ./install.sh             # Material GRUB (and the core)
sudo ./install.sh --with plymouth   # also the boot splash
```
