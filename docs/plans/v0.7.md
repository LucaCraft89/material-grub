# 0.7.0 plan: optional GUI, single-seed theme, overrides

Status: PLAN ONLY, approved by the maintainer 2026-11-18. Branch `release/0.7.0` (from `release/0.6.0`, which is not merged into main yet). One PR, one commit per item.

## Context

0.6.0 ships a curses TUI installer, four styles, per-entry palettes baked at build time, and Ventoy support. There are no per-user per-entry overrides, no single-colour mode, no Python conf writer, no install log, and no installed-state API besides `material-grub doctor --json`. 0.7.0 adds an optional GUI (never installed by default, TUI unchanged), a single-seed colour mode in TUI and GUI, and a shared `overrides.json` so TUI, hand edits and GUI all drive the same pipeline.

## Decisions (maintainer, 2026-11-18)

- GUI is a local web UI: stdlib Python server on 127.0.0.1 plus HTML/JS/CSS front end. M3 Expressive, forest-green seed, Google Sans Flex (already in `fonts/`), animated squiggly progress bar, drag and drop, live preview.
- Root via `pkexec` per action on one fixed helper, with a polkit policy in the GUI package. The GUI itself never runs as root.
- Single-seed mode is a pure tint: every entry uses the one seed's palette.
- Customisations live in `/etc/material-grub/overrides.json`, read by the existing pipeline. Ventoy gets an equivalent file on the stick.
- No prebuilt downloads, Python 3.8 minimum for installer-time code, stdlib + Pillow only at runtime.
- Assistant stops and asks the maintainer before anything unclear, and announces every `sudo`/`pkexec` (fingerprint reader) before running it.

## Answered by the maintainer (2026-11-18)

1. Window shell: the default browser (no webview dependency).
2. The 32 seed colours: the maintainer trusts the assistant's pick (curated, M3-friendly; listed in item C1 and shown in the TUI/GUI for review).
3. Packaging: `material-grub-gui` is a separate package in rpm/deb/arch, the same way the latest packaging commit added the new commands, and only the repo packages offer it. A source install gets it through an `install.sh --with-gui` flag. The main package and the TUI never install it by default.

## Key facts from exploration (constraints)

- Runtime (install time) has Pillow only. `materialyoucolor` exists only in the build venv (`requirements.in`). Seeds are baked into `palettes.json`, `scenes2/*/bg` and `icons`. Colour changes therefore need a re-render, not just a conf edit.
- Conf keys: `mgrub.py:101-112` (`CONF_DEFAULTS`, `CONF_CHOICES`). Writer exists only as sed in `install/install.sh:166`. Strict checks: `tui.py CHECK`, `cmd_doctor.py:64`.
- Reusable importable code: `mgrub.load_conf`, `monitors.detect`, `ventoy_sticks.detect/check`, `tui.build_steps/answers/command_line`, `cmd_doctor.Doctor`, `mgsafe.read_last_error`, `mgscenes.Renderer` (pure Pillow; `render_entry`, `render_class`, `Renderer.pal` is a plain dict).
- Not reusable as-is: `Installer` (sys.exit/die/print), `cmd_ventoy.py` (module globals), `cmd_classes.py` (argv globals). Refactor to functions or shell out.
- Ventoy limits: `menu_class` key at most 31 chars, case-sensitive substring, class without PNG shows black; `menu_alias`/`menu_tip` unused today. User icons need a per-class scene per resolution.
- Light/dark is a process global (`MG_SCHEME`); pass `dark=` explicitly in the GUI.
- `bg` backgrounds are palette-baked at build time, so live seed preview needs `render_scene.panel` ported into `mgscenes` (using the cached glyph PNGs rather than rsvg).

## Order of work

### A. Foundations (tests first)
1. **Plan doc and branch.** `docs/plans/v0.7.md`, `release/0.7.0`.
2. **[DONE] Python conf writer.** `mgrub.write_conf(path, updates)`: atomic temp-file + rename, preserves comments, validates with `CONF_CHOICES`. `install.sh --set` keeps working. Document `SCHEME`, `MODE`, new keys in `install/material-grub.conf`.
3. **[DONE for the installer; the Ventoy command is refactored in D5 where the GUI needs it] Refactor for reuse.** `cmd_ventoy` main to functions, a callable `Installer` API (no sys.exit) or a stable `--json` event stream (`--progress json`: step, percent, log line; done as `--progress json` in `install/installer.py`, which implies `--yes` and never prompts, and turns stray prints and child output into `log` events, ending with a `done` event). Chosen: the event stream, because the GUI shows verbose logs and the squiggly bar, and it keeps one code path.
4. **[DONE] Install log.** Persistent `/var/log/material-grub/install.log` (and the same in the event stream), so TUI and GUI share it.
5. **[DONE] Status API (`doctor --status-json`; update check lives in the GUI).** Extend `doctor --json`: installed, version, style, scheme, seed mode, overrides valid, update available.

### B. overrides.json (core, used by CLI, TUI, GUI)
1. **[DONE] Schema v1** (`install/bin/mgoverrides.py`: entries are a list of rules `{match:{key|class|title}, name, color, icon, hidden}`, plus `seed`, `groups`, `order`) `/etc/material-grub/overrides.json`, versioned and strictly validated (new `mgoverrides.py`): `{version, seed:{mode:"multi|single", color}, entries:{<key or match>:{name,color,icon,hidden}}, order:[...], groups:{linux_first|windows_first|custom}, ventoy:{...}}`. Unknown keys warn, bad values rejected, and a bad file never breaks the boot (falls back to defaults, per `mgsafe`).
2. **Pipeline hooks.** `cmd_classes.py` applies name/order/group/hidden overrides; `cmd_scenes.py`/`mgscenes` apply colour/icon overrides by overriding `Renderer.pal[key]` and glyph aliases. Idempotent annotated cfg behaviour preserved.
3. **[DONE] Colour science at runtime.** Instead of a hand-written HCT port (the current 2025 Expressive spec is too large to port faithfully), the pure-Python part of `materialyoucolor` (MIT, no quantizer) is vendored in `vendor/materialyoucolor` and shipped as `bin/materialyoucolor`; `install/bin/mgpalette.py` wraps it (`scheme(seed, dark)`). `tests/test_palette.py` checks it gives byte-identical colours to the build's pinned release.
4. **Presets.** Export/import a single JSON preset file (`overrides.json` plus conf style/scheme), stored under `/etc/material-grub/presets/`.
5. **Doctor/sanity checks.** Config validity, overrides validity, missing icon files, key-length for Ventoy, with `--json`.

### C. Single-seed colour mode
1. **32-colour palette.** Curated list (maintainer approves) in `scripts/palettes.py` data and mirrored for TUI/GUI.
2. **Build/runtime.** `SEED_MODE=multi|single`, `SEED=#RRGGBB` in conf. Single maps every `PAL[key]` to the seed's scheme. Bake `bg/icons` per seed (reuse the build pipeline; needs rebuild like scheme).
3. **TUI.** New steps `SEED_MODE` and `SEED` (grid of 32 swatches, truecolor with 256-colour fallback, hex entry). Update `CHECK`, `answers`, `command_line`, `installer.apply_answers`, `doctor.config`, `tests/test_tui.py`.
4. **Ventoy.** Same keys in the stick conf.

### D. GUI backend (`gui/`, optional)
1. **Server.** `material-grub-gui` (stdlib `http.server`/asyncio, 127.0.0.1, random port, one-time token, strict origin/Host checks, no CORS). JSON API: status, conf, overrides, presets, entries (from `entries.json`), preview, sticks, logs (SSE).
2. **Live preview.** `Renderer` at reduced height, cached, debounced; per-entry and per-style (rail/clean/list/split, light/dark). Measure render time first (not yet measured).
3. **Privileged helper.** `/usr/libexec/material-grub-gui-helper` with a fixed verb list (apply, install, update, uninstall, write-overrides, ventoy-apply); input is validated JSON on stdin, writes only under `/etc/material-grub/` and calls existing tools. Polkit policy `org.material-grub.gui.policy`.
4. **Update flow.** Checks the release, runs the install with the event stream into the UI, including sanity and config checks and rollback reporting from `mgsafe`.
5. **Ventoy.** Stick detection (`ventoy_sticks`), per-file/pattern name (`menu_alias`), tip (`menu_tip`), class/icon/colour mappings, user SVG/PNG/JPEG upload (rasterised to PNG in-process with Pillow; SVG via `rsvg-convert` already required by the installer, else a clear error). Writes the stick's overrides file and re-runs `cmd_ventoy`.

### E. GUI front end (`gui/web/`)
1. **Design system.** M3 Expressive tokens from forest-green seed, Google Sans Flex via `fonts/`, spring/shape-morph animations, dark/light, `prefers-reduced-motion` respected. No CDN: all assets vendored (offline, licence in `THIRD_PARTY.md`).
2. **Shell.** Left rail: Overview, Style, Entries, Colours, Ventoy, Presets, Update, Logs.
3. **Entries editor.** Drag-and-drop ordering, windows-first/linux-first, per-entry name/colour/icon, hints (tooltips) on every control, live preview pane.
4. **Style and colour.** Style switcher (4 styles), light/dark, single vs multi seed with the 32-swatch picker plus custom.
5. **Status and update.** Installed/version/health cards; centred modal with the animated squiggly progress bar and verbose log stream; sanity and config check results.
6. **Ventoy editor, presets UI.**
7. **No build step** if possible (plain ES modules), so nothing is prebuilt or shipped as a blob.

### F. Packaging, docs, CI
1. **Packaging.** Separate `material-grub-gui` (rpm `%package gui`, deb second stanza, arch split package with `optdepends`); main package never pulls it in. `install.sh --with-gui` for source installs; TUI does not offer or install it by default. `bump_version.py` extended if the GUI has its own version line.
2. **Docs.** `docs/gui.md`, `docs/customising.md` rewritten around `overrides.json`, README, CHANGELOG 0.7.0, screenshots.
3. **Tests.** Unit tests for writer, schema, palette port, event stream, helper verb validation, API handlers (stdlib `unittest` style). Headless browser smoke via Playwright/Chrome only in CI (not required locally). Extend pipeline/golden tests with overrides. CI jobs: `gui` (API + helper), package install/upgrade of the GUI package, Ventoy-in-QEMU with an alias/custom icon.

## Risks

- Large scope: ship in order A, B, C (usable from CLI/TUI alone), then D-E. Each is a green, releasable step.
- Pure-Python HCT port drift from `materialyoucolor`; mitigated by comparison tests.
- Local web server attack surface (any local page could probe it): token, Host/Origin check, no wildcard CORS, helper accepts only whitelisted verbs.
- Live-preview speed unmeasured; may need lower-res previews and caching.
- Ventoy: key-length and rule-count limits, black screen for missing class PNGs, only QEMU-verified; custom icons multiply theme size (8 MB at 1080p per resolution).
- Overrides must never make GRUB unbootable: apply through `mgsafe.guarded` with validation and rollback.
- Immutable/ostree systems use a different state dir, so the helper must honour it.

## Verification

- `tests/run.sh` (lint, unit, pipeline, golden), plus `gen_distro_table.py --check`.
- Overrides: golden-config test with names/order/colours applied; invalid file falls back and `doctor` reports it.
- GUI: start server, drive via browser tools (screenshots of each tab, live preview change, drag reorder, update modal with fake event stream), no console errors.
- Privileged path: `pkexec` apply on this machine (will ask you for the fingerprint, announced first), `material-grub doctor --json` shows the new state; rollback tested with a deliberately broken override.
- QEMU/OVMF boot smoke for single-seed and a custom-order theme; Ventoy QEMU smoke with an alias and a user PNG.
- Package install/upgrade for the GUI package in the existing `packages` CI job.

## Out of scope

Native toolkit GUI, Windows/macOS, editing GRUB itself beyond the theme, downloading prebuilt themes, cloud preset sharing.
